# Диктовки: флоу и UX

> Все решения по интерфейсу, которые диктовал пользователь.
> Добавлять сюда каждое решение.

---

## 2026-09-16

### Старт
- При открытии → сразу окно чата, не список сессий
- Список сессий доступен через свайп/переход
- Сервер opencode запускается сам (часть RPM), пользователь не знает о нём
- Показывать индикатор подключения (● зелёная/серая)

### Чат
- Лента сообщений как в мессенджере
- Стриминг ответа в реальном времени
- Индикация активных тулов (tool status)

### PTT (Push to Talk)
- Кнопка для голосового ввода
- Один флоу: зажал → запись → отпустил → STT
- Тумблер в настройках: сразу отправлять распознанное ИЛИ вставлять в поле
- Позиция кнопки: лево/право (настройка для левшей/правшей)
- **Способ ввода (новый пункт настроек, 3 опции):**
  - только текст с инпута (без PTT-кнопки)
  - текст + PTT (оба способа)
  - только диктовка (PTT без текстового инпута)

### Permission
- Больше 2-х вариантов: Разрешить / Всегда разрешить / Запретить / Всегда запретить
- Формат: понятное описание что именно просит агент
- Пока не отвечен — сессия ждёт

### STT/TTS
- Только локально (без облака)
- Как в Speech Note (mkiol/dsnote): скачивание моделей через UI
- whisper.cpp для STT, Piper для TTS
- Модели хранятся локально, выбираются в настройках

### Уведомления
- Звук "дзинь" по завершении работы агента
- Звук при запросе permission
- Настройки включать/выключать

### Озвучка ответов (TTS) — 3 опции в настройках
- **Авто + кнопка повтора:** автоматически озвучивает каждый ответ,
  есть кнопка 🔉 для повторного прослушивания
- **Только кнопка:** не озвучивает автоматически, но показывает
  кнопку 🔉 на каждом ответе для ручного воспроизведения
- **Нет озвучки полностью:** нет авто, нет кнопки (TTS отключён)

### Зависимые настройки (условная блокировка)
Некоторые настройки зависят от других. Если предпосылка не выполнена —
настройка заблокирована/недоступна:

- **Позиция PTT (лево/право)** — доступна ТОЛЬКО если способ ввода
  включает PTT (текст+PTT или только диктовка). Если PTT отключён
  (только текст) — пункт заблокирован.
- **«Сразу отправлять распознанное»** — доступна только при включённом PTT.
- **Озвучка ответов (авто / кнопка 🔉)** — доступна ТОЛЬКО если TTS-модель
  (Piper) скачана и настроена. Если моделей нет — все 3 опции озвучки
  недоступны.
- **STT-связанные опции** (распознавание) — только если STT-модель
  (whisper.cpp) скачана.
- Заблокированные пункты: серый цвет / недоступен, а не скрывать —
  чтобы пользователь видел, что в настройках есть эта опция, но она
  требует действия (скачать модель, включить PTT).

### opencode serve
- Идёт вместе в RPM-пакете
- Пользователь ставит → открывает → работает
- Не нужно отдельно запускать/настраивать
- Пользователь вообще НЕ знает о существовании сервера

### Жизненный цикл сервера (паттерн RAII / замыкание)
- При конструировании приложения → сервер `opencode serve` создаётся/запускается
- При закрытии приложения → в деструкторе вызывается stop сервера
- Пока приложение работает (даже свёрнуто/в фоне) → сервер жив
- Реализация: структура `ServerGuard { child }`, `Drop` останавливает процесс

### SSH к телефону
- Не нужен для сборки — собираем на ноуте через кросскомпиляцию
- Только для установки готового RPM

### Permission (уточнение)
- Не придумывать варианты в GUI — рендерить ровно то, что сервер прислал
- Если сервер вернул 2 варианта — 2 кнопки, если 3 — 3, если 4 — 4
- Описания тоже от сервера, не нашего製

### Меню (уточнение — БЕЗ кнопок!)
- Кнопки в шапке ОТМЕНЕНЫ. Палец не должен тянуться вверх экрана.
- Навигация только свайпами:
  - Экран чата: свайп **вправо** → настройки ТЕКУЩЕЙ сессии (локальные)
  - Экран списка сессий: свайп **влево** → настройки ГЛОБАЛЬНЫЕ
- PullDown меню допустимо ТОЛЬКО на экране списка сессий (нет конфликтующего скролла)
- На экране чата PullDown НЕ используется (конфликтует со скроллом ленты)
- Это продумано для удобства использования одной рукой:
  жесты снизу/из середины, не из шапки

### Язык интерфейса (уточнение)
- Текущий: только английский (en)
- Будущее: конфиг для переводов (i18n/{lang}.json)
- **ЖЁСТКОЕ ПРАВИЛО:** новый язык появляется в списке ТОЛЬКО когда
  файл перевода ПОЛНОСТЬЮ заполнен (все обязательные поля на месте).
  Не полностью переведённый язык НЕ показывается.
  Это исключает смесь языков на одном экране.

## 2026-09-19

### Старт (уточнение к «Старт»)
- При открытии невозможен пустой чат: открывается **последняя сессия с её историей**.
- Если последней сессии нет (первый запуск, удалены все сессии) — она
  **автоматически создаётся** при старте, чат готов к работе.
- После «Delete all sessions» сразу создаётся свежая сессия.

### PTT (уточнение: холд + тап)
- Основной флоу: **зажал → запись → отпустил → STT** (hold-to-talk).
- Короткий тап по кнопке микрофона — тоже работает как переключатель:
  тап = начать запись, повторный тап = остановить и распознать.
- Минимальная длительность удержания для STT после отпускания — 400 мс.

### Накопление распознанного текста
- Новый фрагмент STT **добавляется в конец** уже надиктованного текста
  в поле ввода (с пробелом), НЕ заменяет его.
- Пользователь может надиктовать несколько фраз, потом отправить всё разом.

### Авто-отправка (уточнение к тумблеру «сразу отправлять»)
- Когда тумблер «сразу отправлять распознанное» включён (или режим «только
  диктовка») — распознанный текст уходит агенту НАПРЯМУЮ, минуя поле ввода.

### Персист настроек (реализовано)
- Настройки интерфейса сохраняются в dconf (`/apps/harbour-opencode/*`):
  способ ввода, позиция PTT, режим озвучки, звуки, авто-отправка, язык UI.
- Выбранные STT/TTS модели и язык распознавания — в
  `~/.local/share/harbour-opencode/voice_state.json`.
- Всё переживает перезапуск приложения.

### Смена сессии (уточнение, реализовано)
- При открытии/создании/форке/удалении сессии лента тулов очищается —
  баблы вызовов инструментов от прошлой сессии НЕ должны примешиваться
  к истории новой.
- Под каждым сообщением (текстовым бабблом) показывается **маленькое время
  отправки** (местное HH:MM) — реальное время создания сообщения из сессии,
  не время загрузки.

### Очистка истории — УБРАНА
- Опции «Очистить историю» в настройках сессии **больше нет**.
- Причина: API opencode не позволяет удалять сообщения сессии (только
  всю сессию целиком) — значит «очистить историю» было бы фикцией.
  Лучше явная невозможность, чем кнопка, которая ничего не очищает.
- «Компактнуть сессию» защищена протектором: `RemorsePopup` «Сжать
  историю?» с отменой по тапу (как защита «Удалить сессию»).
## 2026-09-19: TTS-флоу (Auto / Button / Off)

- **Озвучка = весь ответ целиком.** ИИ на один запрос может прислать несколько бабблов одного ответа, поэтому озвучивается **собранный в воркере `text`** (idle), а не каждый баббл. Кнопка 🔉 на баббле тоже озвучивает текст этого ответа-части (как и задумано).
- **Архитектура озвучки:** воркер `run_tts` гоняет `PIPER_BIN` (`/usr/libexec/harbour-opencode/piper/piper`, ставится в RPM вместе со всем каталогом `piper/`) с `current_dir(PIPER_HOME)` (там `espeak-ng-data`), кладёт WAV в `/tmp/harbour-opencode-tts.wav` и пушит в pending строку `[[tts]]<путь>`; QML в `poll()` видит её, НЕ создаёт баббл, а играет через `MediaPlayer` (`ttsPlayer`). Модуль `audio::tts::PiperTts` не используется (feature `voice` не включена в сборке).
- **Демки на бабблах:** кнопка 🔉 (иконка `icon-m-volume`) — только на ответных (не-user) бабблах, видна при `ttsMode !== off` и `ttsModelReady`; у пользователя этой кнопки нет. Автоповтор — режим `auto`.
- **Правило протокола: ЕДИНЫЙ ИСТОЧНИК строк.** Никаких строк-магиков в коде. Значения команды/режима — только через **enum Rust** (`TtsMode` в `voice.rs`, `Cmd` в `cmd.rs`) со строкой через `as_str()`; QML НЕ дублирует значения «в лоб» — он использует **readonly property-константы** (см. ниже) и строки протокола идут через них (/мост) в Rust-парсер. Пример: не писать `"auto"` в QML — есть `appWindow.modeTtsAuto`; в Rust не сравнивать `=="auto"` — только `TtsMode::parse`/матч по enum.
- **`TtsMode` enum** (voice.rs): `Auto|Button|Off`, `as_str()`, `parse(s)`, `Default = Button`. Значение хранится в `VoiceState.tts_mode` (`Arc<Mutex<TtsMode>>`), персистится в `voice_state.json` как `tts_mode` ("auto"|"button"|"off") и в dconf `/apps/harbour-opencode/ttsMode`.
- **`tts_mode` в CSS-**статусе-встороне: в `voice_status_json` НЕ слать режим (QML его берёт из dconf `ttsModeSetting`, default `"button"` — БЫЛ баг-дефолт `"text"`, исправлен).
- **Условия активности:** опции озвучки (ComboBox в GlobalSettingsPage) и кнопка 🔉 доступны только если выбрана и СКАЧАНА TTS-модель — `appWindow.ttsModelReady` (выставляется в `poll()` из `chosenTts` + `voiceModels.downloaded`); иначе селектор и кнопки выключены/скрыты.

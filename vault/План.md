# Sailfish-клиент для opencode (Rust + QML)

**Статус:** 🟢 Рабочий прототип на телефоне (2026-09-20): GUI-чаты + сессии, голосовой стек (запись PTT → whisper → STT → авто-отправка), каталог моделей с прогрессом, звуки, персист настроек, `resume` последней сессии. **Де-саботаж выполнен** (commit `b462460`): восстановлены протокольные константы голосового модуля в корневом QML и чистая `GlobalSettingsPage`; `VoiceModelsPage.qml` = полное ТЗ (фильтр языков, сворч. секции Downloaded/Recognition/Synthesis, параллельные загрузки, отмена, выбор, удаление с RemorseItem). Впереди: флоу TTS-озвучки на телефоне, permission-flow, i18n-переводы, Harbour-валидация.
**Цель:** Нативное приложение для Sailfish OS (Xperia 10 IV, aarch64), которое подключается к `opencode serve` и даёт: текстовый чат + PTT (зажал-поговорил → STT) + голосовые ответы (TTS) + живой статус тулов и запросы разрешений.

## Стек
- **Клиент:** Rust (`reqwest` + `tokio`), обёртки типов под `serde` из OpenAPI-спеки opencode.
- **UI:** QML / Silica (Qt 5.5, sil-qt5). Связь Rust ↔ QML: `qmetaobject-rs` (план) — но см. «Rust-шаблоны Sailfish» ниже: есть готовая практика через `qobject-compiler` (проект R1tschY).
- **SSE-стрим:** `/global/event` — единственный источник состояний.
- **STT/TTS:** локальные (whisper.cpp + Piper), **модели скачиваются пользователем через UI** из каталога (как в Speech Note, mkiol/dsnote). **В RPM модели НЕ включаются** — только движки (whisper-cli, piper, opencode) и само приложение.
- **Сборка:** на ноутбуке (не на телефоне!). Целевой таргет `aarch64-unknown-linux-gnu`. Сборка RPM — через Sailfish SDK / `sfdk build` (не qmake: наш бинарь собирается `cargo`, `.pro` только как заглушка для QtCreator/QML-редактирования).
- **opencode serve:** идёт в составе RPM-пакета, запускается сам при старте приложения (RAII). Пользователь ничего не настраивает.
- **Запись/воспроизведение звука:** чистый Rust через `cpal` (ALSA) + `hound` (WAV). Внешних бинарников (arecord/aplay) не требуется; единственная системная зависимость — `libasound.so.2` (есть на любом Sailfish).
- **Язык интерфейса:** en (единственный), но через конфиг i18n — для будущих переводов (язык активен только при 100% заполнении).

## Rust-шаблоны Sailfish (проверено 2026-09-16)
- **`R1tschY/harbour-rust-example`** — эталон: Rust + QML, `qobject-compiler` для связи, `CONFIG += sailfishapp`, сборка `sfdk build`/`sfdk deploy`. **Не компилируется под i486** (эмулятор) — только armv7hl/aarch64. У нас aarch64 — норм.
  - https://github.com/R1tschY/harbour-rust-example и https://github.com/R1tschY/harbour-sailify (сложнее).
- **Whisperfish** (Signal-клиент) — самый крупный Rust-проект Sailfish: Rust + QML + свой `Cargo.toml` + `.desktop`/иконки/RPM. Аудио — GStreamer (у нас выбран cpal, но GStreamer-путь Whisperfish — референс если cpal не зайдёт). 
  - Ключевой крэйт от автора: **`sailo-rs`** (обёртка над `sailfishapp` + Docker-образы с 3 Rust-компиляторами для кросс-сборки armv7hl/aarch64/i486 и RPM-валидатор).
  - https://github.com/R1tschY отличная практика; Whisperfish репо: gitlab.com/whisperfish/whisperfish.
- **Важный нюанс из форума Sailfish (2025):** свежий Rust/Cargo (edition 2024) **несовместим** со старым sfdk-тулчейном (там Cargo 1.75-nightly). Решения: (а) свежие sfdk-таргеты Jolla SDK 5.x, (б) Docker-образы sailo-rs/CODeRUS, (в) наш текущий путь — прямая кросс-сборка `cargo build --target aarch64-unknown-linux-gnu` на ноуте, спецификация RPM пишет бинарь в `/opt/...` без qmake.
- **Вывод для нас:** БЕРЁМ из шаблонов только упаковочную обвязку (структуру `rpm/*.spec`, `.desktop`, иконки hicolor, практики sfdk build/check). НЕ переносим всю схему (qmake-такс нам не нужен). Продолжаем на существующей базе.

## Архитектура
```
QML (Silica UI)
  │   сигналы/свойства (qmetaobject-rs)
  ▼
Rust core (opencode-client)
  ├── api/        — HTTP-клиент к opencode server (reqwest)
  ├── types/      — serde-типы событий, сообщений, permission, session
  ├── state/      — машина состояний (session/tool/permission)
  └── event/      — SSE-стрим, парсер
  │
  ▼
opencode serve  (на телефоне или LAN)
```

## Машина состояний (из OpenAPI-спеки)

### Сессия
- `idle` | `busy` | `retry { attempt, message, next }`

### Тул
- `pending` (ждёт input) → `running` → `completed { output }` | `error { error }`

### Разрешения (permission)
- `permission.updated` (запрос от сервера)
- Варианты ответа — ровно то, что сервер прислал (не придумываем)
- Ответ шлётся: `POST /session/:id/permissions/:permissionID { response, remember? }`

### Сообщения
- user/assistant + ошибки (ProviderAuth, Api { retryable }, Aborted, OutputLength, Unknown)

### События SSE (полный список)
`server.connected`, `session.created|updated|deleted|diff|error|status|idle|compacted`,
`message.updated|removed`, `message.part.updated|removed`, `permission.updated|replied`,
`file.edited`, `todo.updated`, `command.executed`, `file.watcher.updated`, `vcs.branch.updated`, `pty.*`, `tui.*`

## Вопросы на проработку
1. ~~Где живёт `opencode serve`~~ **РЕШЕНО (2026-09-16):** на телефоне, бинарь в `opt/` в RPM, RAII-жизненный цикл. Авто-порт `--port 0` — конфликтов с существующим сервером нет.
2. ~~Кросскомпиляция~~ **РЕШЕНО:** обычная кросс-сборка `cargo build --target aarch64-unknown-linux-gnu` + linker `aarch64-linux-gnu-gcc` уже работает; `libasound2-dev:arm64` установлен; паги PKG_CONFIGPATH через `PKG_CONFIG_PATH_aarch64-unknown-linux-gnu` в `.cargo/config.toml`.
3. ~~Нужны ли dev-заголовки Qt~~ **РЕШЕНО:** на этапе RPM-обвязки — да, только внутри build-env sfdk; для чистой сборки Rust-бинаря qmake/Qt не нужны.
4. ~~Авторизация к opencode serve~~ **РЕШЕНО (2026-09-19):** `OPENCODE_SERVER_PASSWORD` → basic auth в api-клиенте; приложение на телефоне успешно подключается к своему локальному серверу (по серверному порту из лога).
5. **Микрофон-пермишены в sailjail** — что именно указывать в `.desktop` (X-Permissions / sandbox policy), свериться с Whisperfish.
6. **Насколько большие whisper-модели потянет телефон** (Xperia 10 IV, aarch64): проверить скорость ggml-base vs small на устройстве. Каталог моделей должен помнить про «slow on phone».

## Факты, подтверждённые на живом сервере (2026-09-16)
- `GET /global/health` → `{ healthy: true, version }` — работает.
- `GET /global/event` (SSE): реальный формат события **без обёртки `directory`**:
  ```json
  {"payload":{"id":"evt_...","type":"server.connected","properties":{}}}
  ```
  Поле `id: evt_*` есть у каждого события (в нашей схеме не используется).
- `server.heartbeat` — периодический пинг, в типы добавлен, UI должен игнорировать.
- `POST /session` тело `{}` достаточно; возвращает `Session` с полями `id`, `slug`, `projectID`, `directory`, `title`, `version`, `time`.
- `session.created` приходит в SSE с `properties.info: Session` — наша структура типов совпадает.
- Client smoke-test: `OPENCODE_SERVER_URL=http://127.0.0.1:4096 ./target/debug/opencode-client` — подключается к SSE, логирует события. (Тесту мешает, что на 4096 уже висит serve бота.)

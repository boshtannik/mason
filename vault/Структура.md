## Потоки данных

**Входящий (SSE):**
```
opencode server --SSE(200)--> sse.rs --> Event --> state/* (FSM) --> bridge --> QML
```

**Исходящий (действия):**
```
QML (кнопка/инпут) --> bridge --> api/* --> opencode server
```

**Permission (диалог):**
```
opencode --permission.updated--> state/permission → QML PermissionDial
Пользователь: Allow/Deny → api/permission.answer → server
```

**PTT (голос, локально):**
```
QML PTTButton (зажал) → аудио/recorder (cpal/ALSA) → WAV 16k mono
  → STT (whisper-cli, локальная модель из каталога) → текст → чат/инпут
Ответ (текст) → TTS (piper, локальный голос из каталога) → WAV → проигрывание (cpal)
```
Движки (whisper-cli, piper) — в RPM; МОДЕЛИ (ggml-*.bin, piper *.onnx) — скачиваются пользователем в Глобальных настройках из каталога (как Speech Note), в RPM не входят.

## Принцип протокола (обязательно)

**Единый источник строк протокола — enum в Rust.** Никаких строк-магиков:
- Команды (`Cmd` в `cmd.rs`), движки (`engine::*` в `voice.rs`), режимы (`TtsMode` в `voice.rs`) — enum/константа с `as_str()/parse()`.
- QML **не дублирует значения «в лоб»**: строки протокола — только через **readonly property-константы** корня (`cmdLang`, `cmdSelectStt`, `cmdSelectTts`, `cmdDownload`, `cmdDownloadCancel`, `cmdDelete`, `cmdRecordStart/Stop`, `cmdStt`, `engineStt`, `engineTts`, `stateDownloading`, `stateError`, `modeTtsAuto/Button/Off`) и передаются в мост. **Эти 14 констант неприкосновенны** — их удаление ломает `VoiceModelsPage` (case 2026-09-20, commit `b462460`).
- В Rust запрещено сравнивать строки (`=="auto"`, `match strings`): только `TtsMode::parse` / матч по enum.
- Персист QML → dconf-ключи (`/apps/harbour-opencode/*`) живут в QML, не нарушают это правило (это хранилище настроек, не протокол).

## Сборка (на ноутбуке, не на телефоне)

**Актуальный рабочий путь (2026-09-16):**
- Прямая кросс-сборка: `cargo build --target aarch64-unknown-linux-gnu`
- `.cargo/config.toml`: linker `aarch64-linux-gnu-gcc`, `PKG_CONFIG_PATH_aarch64-unknown-linux-gnu=/usr/lib/aarch64-linux-gnu/pkgconfig`
- `libasound2-dev:arm64` установлен (для cpal→alsa-sys). Системная зависимость на телефоне: только `libasound.so.2`.
- Проверено: бинарь и примеры собираются под aarch64, libasound линкуется корректно.

**RPM-пакетирование (после GUI, из шаблонов Sailfish):**
- `sfdk build` / `sfdk deploy` (Sailfish SDK); `sfdk check` — Harbour-валидация.
- Репо-структура по tar_git: `rpm/*.spec` (spec генерится напрямую, changelog из git), `.desktop`, иконки hicolor, cover.
- Rust-спека берёт бинарь из `cargo build` (см. практики R1tschY/harbour-rust-example и Whisperfish), НЕ через qmake.
- Внимание: свежий Cargo (edition2024) может не завестись в старом sfdk-тулчейне — нацеливаемся на Jolla SDK 5.x или Docker-образы (sailo-rs/CODeRUS).
- Вариант B (исторический, для справки): Sailfish SDK (OS1), `sb2 -t SailfishOS-5.1.0.11.aarch64`.
